# Block 2 — Technique Consolidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Block 2's eight pre-evidence `PROGRAM_OUTLINE` rows with an evidence-cited 8-week training block, shipped into the app.

**Architecture:** Twelve new decision-shaped questions extend the existing catalog; the whole 42-question pack regenerates from Qdrant with a committed per-passage citation manifest. A cited Block 2 document is written against that pack and gated by `tools.check_citations`. The app then gains `PROGRAM_B2` as a second global script, plus fixes to block-progress arithmetic and the school-term week.

**Tech Stack:** Python 3.14 + pytest, Qdrant + Ollama (on the Z840, via Brain_Dump's `indexer`/`query` modules), React 18 UMD + esbuild (transform-only, no bundling), Node for build.

## Global Constraints

- **Every question asks what COACHES say.** No question may mention this athlete — `tests/test_synthesis_questions.py` enforces it.
- **No transcript text enters git.** `transcripts/` and `evidence/` are gitignored. The citation manifest stores a sha256, never a quote.
- **Every prescription in the Block 2 document carries a citation handle or `[JUDGMENT — NO COVERAGE]`.** There is no third category.
- **Citation handles are re-resolved against `evidence/2026-08-12/`**, never copied from the spec — the spec's handles come from the 2026-08-11 pack and regeneration reorders near-tied passages.
- **Version bump is mandatory** on any commit touching `docs/src/app.jsx`, `docs/app.js` or `docs/index.html`: `PROGRAM v<X.Y.Z> · <date>` in `app.jsx`. Target for this work: `v3.6.0 · 2026-08-12`.
- **Never run `git add -A`** in this repo (raw transcript text and `docs/key.js` must never be committed). Stage named paths only.
- **`docs/app.js` is generated.** Never hand-edit it; edit `docs/src/app.jsx` and run `npm run build`.

## Deviations from the spec (deliberate, decided during planning)

The spec at `docs/superpowers/specs/2026-08-12-block2-design.md` specified two mechanisms that do not work against this codebase. Both are corrected here.

1. **Spec said:** extract program data to `docs/src/program.js` and have `app.jsx` import it.
   **Problem:** `build.mjs` sets `bundle: false` with the comment *"no imports in the source; everything is a page global."* An `import` would emit an unresolved ESM statement into a classic script.
   **Fix:** `docs/src/program.js` becomes a **second esbuild entry point** emitting `docs/program.js`, loaded by a `<script>` tag *before* `app.js`. Top-level `const`s are visible to `app.js` exactly as `sbSync` (declared in an inline `index.html` script) already is. No import syntax anywhere. `build.mjs` switches `outfile` to `outdir`, `docs/sw.js` adds `./program.js` to `APP_SHELL` and bumps its cache name.

2. **Spec said:** commit `citations.json` inside the pack via a `!evidence/*/citations.json` gitignore negation.
   **Problem:** git cannot re-include a file whose parent directory is excluded. `evidence/` is excluded, so the negation silently commits nothing.
   **Fix:** the manifest is written to `docs/programs/2026-08-12-citations.json` — outside any ignored directory, next to the document that cites it. No gitignore change at all.

```python
def build_citations(results: list[QuestionResult], *, limit: int,
                    threshold: float, collection: str) -> dict:
    """One record per retrieved passage, committed to git alongside the
    document that cites it.

    Retrieval reorders near-tied results between runs, so `E31.4` on Tuesday
    need not be `E31.4` on Wednesday. This pins each handle to a content hash,
    which proves identity on a later run WITHOUT storing the passage text —
    the pack itself is gitignored transcript material and must stay that way.
    Human-readable auditing comes from the document, which quotes inline.
    """
    entries = []
    for r in results:
        for i, p in enumerate(r.passages, start=1):
            entries.append({
                "handle": handle(r.question.id, i),
                "question_key": r.question.key,
                "note_path": p.note_path,
                "source": p.source,
                "score": p.score,
                "sha256": hashlib.sha256(p.text.encode("utf-8")).hexdigest(),
            })
    return {
        "retrieval": {
            "limit": limit,
            "threshold": threshold,
            "collection": collection,
        },
        "citations": entries,
    }
```

// Block boundaries — the ONE definition. Block progress, week routing and the
