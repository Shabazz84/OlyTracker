# App UI Slim-Down Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut OlyTracker from 10 tabs to 4. The gym screen goes straight to today's work, an in-session warm-up comes back, Log becomes a calendar, and PRs are limited to 10 lifts.

**Architecture:**
- **Pure logic in `program.js`, tested in Node.** The logic the new screens need lives in `docs/src/program.js` as plain functions, covered by Node tests (`tests/js/ui-slim.test.mjs`): PR row mapping, warm-up definition, set counting that excludes warm-ups, log-day set lookup, month grid.
- **`app.jsx` rewires views.** It removes views and builds the new ones on those helpers.
- **Rendering is proven with `olytracker-ui-verify` specs.**

**Tech Stack:**
- React 18 UMD + JSX via esbuild (`npm run build`)
- classic-script globals
- `node --test`
- the `olytracker-ui-verify` skill

**Spec:** `docs/superpowers/specs/2026-10-17-ui-slim-design.md`. Mockups: https://claude.ai/artifact/GYktKetnfqh684f8653JEW (Option A).

## Global Constraints

- **Never delete stored data.** Removing a view must not remove its data:
  - localStorage keys (`oly_summer`, `oly_supp_*`, `sets_*`, `oly_logs`, `oly_prs`) stay.
  - Supabase rows stay.
  - Backup import of an old export must not throw.
- **Week-completion, PR rebuild and the week-16 test day behave exactly as now.** Keep `DAYS_SUMMER`; Block 1 weeks (1–8) keep the summer catalogue.
- **The warm-up never gates anything,** and never counts toward session %, week completion or `expectedTotal`.
- **Version bump:** `PROGRAM v3.18.0 · <date>` in `app.jsx`, plus the CLAUDE.md "Current version" line. Done once, in Task 6.
- **Never point a browser at `docs/`.** Stage with `stage.cjs`.
- **Never `git add -A`.**
- **No new top-level name in `program.js` may clash with `app.jsx`.** They share one global scope; grep `^(const|let|var|function) <name>\b` in `app.jsx` before adding.

## Review Focus

1. **Warm-up ticks inflating session % or week completion.** The athlete ticks the warm-up and the session reads 110%, or a skipped warm-up blocks the week. Pinned: Task 1 `doneSetsFor excludes warm-up`, Task 3 ui-verify.
2. **Block 1 history vanishing with the toggle.** Week 3 must still show its 5 summer days and their logged sets. Pinned: Task 2 ui-verify (`week 3 shows D5`).
3. **Restoring an old backup** (with `oly_summer` and supplement keys) crashing or flipping state. Pinned: Task 4, `importBackup` ignores `oly_summer` (code-read check + ui-verify `eval` seeding).
4. **Two sessions logged on the same date.** The calendar day must show both, not one silently. Pinned: Task 1 `logsOnDate`, Task 5 ui-verify.
5. **A PR row with no data** (e.g. Snatch Pull never logged) crashing the list or showing `undefined`. Pinned: Task 1 `prRow empty`, Task 6 ui-verify.

### Task 1: Pure helpers in program.js

**Files:**
- Modify: `docs/src/program.js` (append a `// ── UI slim helpers` section)
- Create: `tests/js/ui-slim.test.mjs` (loader like `block3.test.mjs`'s `loadProgram`, exposing the names below)

**Interfaces — Produces:**
- `PR_ROWS: Array<{key:string, label:string, ids:string[]}>`. Exactly the spec's 10 rows and id table, in spec order.
- `prRow(prs, row) → {weight:number|null, date:string|null, history:Array<{weight,date}>}`:
  - `weight`/`date` come from the max-weight entry across `row.ids`.
  - `history` merges every id's `history`, sorted by date ascending.
  - Empty → `{weight:null, date:null, history:[]}`.
- `WARMUP = {before:[{id,name,dose,note}], after:[{id,name,dose,note}]}`:
  - **before:** loaded ankle dorsiflexion stretch (`2–3 × 90 s per side`); McGill curl-up / side plank / bird dog as ONE row (`1 round`).
  - **after:** supine pelvic tilt; segmental cat-cow.
  - Names, doses and notes come from the app's `MOBILITY.ankle/core/spine` entries. Keep their `[E…]`/`[JUDGMENT]` tags in `note`.
- `WARMUP_IDS = ['warmup_before','warmup_after']`. Warm-up ticks are stored as `sets_w{week}_{dayId}_warmup_before` / `_warmup_after`, so the existing set sync carries them.
- `doneSetsFor(prefix, keys, getItem) → number`. Counts `done` entries under `prefix`, skipping any key ending in a `WARMUP_IDS` id.
- `logDayId(entry) → string|null`. Returns `d<n>` from the first digit in `entry.dayLabel` (the `inferDaysFromLogs` rule), else null.
- `logDaySets(entry, keys, getItem) → Array<{exId, sets:Array<{weight,done}>}>`:
  - Reads keys with prefix `sets_w${entry.week}_${logDayId(entry)}_`.
  - Excludes warm-up ids.
  - Keeps only sets with a weight or `done`.
- `logsOnDate(logs, date) → Array<[key, entry]>`. All entries with that date, keys included.
- `monthCells(year, month0) → Array<string|null>`. Monday-first grid with `null` pads; ISO dates; length a multiple of 7.

  - `PR_ROWS is the spec's 10 rows`: labels in order. `Split Jerk` ids are exactly `['split_jerk_from_rack','jerk_from_rack']` (not `split_jerk`, not `push_jerk`).
  - `prRow takes the heaviest across ids`: snatch 55 + snatch_from_floor 58 → 58 with that date; history merged and sorted.
  - `prRow empty` → nulls, `[]`.
  - `doneSetsFor excludes warm-up`: keys `sets_w18_d1_snatch` with 2 done and `sets_w18_d1_warmup_before` with 2 done → 2.
  - `logDaySets` returns exercises for `{week:18, dayLabel:'D3 Thu ⭐⭐'}` from `sets_w18_d3_*` only, with no warm-up row.
  - `logsOnDate` returns both of two same-date entries.

  - `WARMUP.before` has 2 rows, `after` has 2 rows. The ankle row's dose contains `90 s`.
